# 0.1.3 验证记录

日期：2026-10-28。环境：单台 Windows 11 x64；本页区分代码/进程检查与物理双机验收。

- 原生自包含 Release 构建通过，39 组原生自检通过；开发构建 0 错误、0 警告。
- 新增 256 次完整控制器回放：速度 100/1500/4000/10000 逻辑单位每秒，接管延迟 0/16/80/160 ms，四方向、正反缩放组合、负坐标。接管时传入 50000 残余量并累计等待期运动，仍先在固定边缘定位；确认后的 30 单位移动保持目标 DPI 距离，返回预测一致，无旧过渡回放。
- 生产 InputOutbox 参与新回放；不可合并起点与普通位置分开，确认前位置拒绝，重复起点/提交/回执不重置，旧序号/旧轮次不能重新激活。点击、滚轮和拖拽按精确目标执行。
- 以假时钟和隔离接收器检查 30/60/144/240 Hz 的边缘保留、过渡中间采样和截止时间；更新目标不延长起步过渡，结束后活动移动直接定位。这是调度模型检查，不是实际显示器首帧测量。
- 直接调用生产 Capture 回调验证：钩子旧屏幕坐标不生成移动，Raw Input 的移动/按钮只转发一次且按序，校准排除旧位移但保留按钮释放；覆盖来源缩放与消息时钟回绕。
- 真实双向 TLS 的 19/31 字节碎片流上分别验证 v3 兼容流程与 v4 起点校准、确认前位移消耗、活动位置和预测返回；此项未经过物理蓝牙无线链路。
- 校准超时、错误连接、取消、锁定与过渡定位失败恢复输入，释放修饰键并停止旧过渡。
- 6 项 Node 测试、JavaScript/资源检查通过；8 个真实原生双进程回环场景通过，包含文件与后台重挂，核对钩子和 Raw Input 注册有效。
- 真实 Electron 五页、传输进度/重试/文字转义、预热设置和 FileList 桥接通过；最小化、关闭到托盘后原生通信和后台注册仍有效，全程未点击桌面。
- 便携 ZIP 的 CRC 检查通过；包内程序、界面归档和原生核心与本次构建一致。安装包嵌入的 ZIP 载荷与便携版逐字节 SHA-256 一致；本地常用直接运行目录已同步到 0.1.3。
- 测试采用独立配置与隔离鼠标接收器；真实 GUI 测试禁用共享输入/剪贴板和蓝牙，不向用户桌面注入测试鼠标。

`crossings.firstDisplayedMoveMs` 表示首次过渡定位请求被接收器接受的本机时刻，**不证明显示器已经呈现**。`entryFrameMs` 是查询刷新率后选取的调度间隔；WinForms 定时器、系统负载、DWM 与无线传输可能延迟实际呈现，不能把模型中的 1–2 个间隔当作实测毫秒数。

实现参考：[Raw Input 的鼠标数据语义](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawmouse)、[GetMessageTime 的消息入队时间与回绕](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getmessagetime)、[GetDeviceCaps 的刷新率查询](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-getdevicecaps)。Raw Input 不采用 Windows 鼠标加速，远端倍率由“指针速度”调节。

尚未执行：物理双机 BLE 快移首个可见位置/轨迹、真实后台跨屏手感、VPN/TUN/Wi-Fi Direct 共存和同设备性能对照。验收步骤见 TESTING.md。本版不宣称已经实测优于原版。

- 8 个真实原生进程回环场景通过：原有 7 项加后台监听重挂，核对键盘/鼠标钩子和 Raw Input 注册仍有效、连接未断开。

- 新诊断位于 `input.preparation`、`input.background`、`input.crossings` 与 `inputQueues`；不记录普通按键字符或剪贴板正文。本机时间不能跨机器相减当作显示延迟。

## 0.1.1 历史验证

日期：2026-10-27。当前验证仍在单台 Windows 11 x64 开发电脑上完成。

- 原生 Release 构建及自包含发布通过；0 个错误、0 个警告。
- 21 组原生自检通过，其中新增 7 组：四方向/负坐标/混合显示器几何；100/125/150/200% 缩放下的逻辑光标；160 ms 确认延迟下先发移动且无确认补发；拒绝/超时/旧轮次/错误连接/定位失败与未确认定位返回；拥堵移动合并、过期和点击顺序；拖拽距离保持；真实双向 TLS 上人为阻塞 bulk 后的接管→移动→按键顺序。
- 回归测试使用隔离的光标接收端与人工时钟，不安装全局输入钩子、不向正在使用的桌面注入测试输入。160 ms 是测试注入的确认延迟，不是物理蓝牙延迟实测值。
- 4 项 Node 界面通信测试、JavaScript 语法/资源检查通过。
- Windows 安装包、便携版与源码包归档检查通过；安装包内的 ZIP 载荷与便携版逐字节 SHA-256 一致，便携版原生核心与通过自检的核心一致；对应源码包 64 个文件与最终项目逐文件核对。
- 两个真实原生进程的回环集成通过：双端配对确认、加密文件、拒收/重试/同名保护、140 个中文文件、可信重连、单端忘记后的重新配对、诊断排除正文与私钥。
- 原始诊断中包含 `input.crossings` 和 `inputQueues`；没有按键字符或剪贴板内容。发送端 `firstMoveMs` 表示首个移动入队耗时，接收端表示首个移动处理耗时，不能跨机相减当作端到端延迟。

未执行：两台物理电脑之间的 BLE 输入、实际光标显示时序、VPN/TUN 与 Wi-Fi Direct 共存；未宣称固定毫秒数或优于原版。验收清单见 TESTING.md。

## 0.1.0 历史验证

日期：2026-10-27。测试在开发用的单台 Windows 11 x64 电脑上执行。

已通过：

- 原生核心 Release 构建，0 个编译错误、0 个警告。
- 14 项原生自检：路径安全、Unicode、配对随机数承诺、证书绑定配对码、输入二进制编码、消息边界、DPAPI 身份保存、碎片化字节流上的双向 TLS、接收确认、文件与空目录传输、校验失败清理和图片尺寸限制。
- 4 项 Node 测试：请求关联、原生错误传播、超时清理、核心不可用的提示。
- 两个独立原生进程的回环集成：双方确认配对、UTF-8 文件传输、拒收与重试、同名保护、140 个中文文件的文件夹传输、可信身份重连、单端忘记身份后的重新配对，以及诊断中排除剪贴板和私钥。

- 真实 Electron 界面：五个页面渲染；传输进度、重试入口、剪贴板文字转义用例；未发现 JavaScript 或 CSP 错误。

尚未验证：

- 两端各自开启 VPN/TUN、连接不同网络时的 Wi-Fi Direct 建立及与原上网连接共存。
- 与 TwinDesk 在同一组物理设备上的延迟、吞吐和资源占用对照。

单机回环、内存碎片化流和硬件初始化均不等同于物理双机联调；本版不宣称已实测全面优于 TwinDesk。
具体物理设备验收步骤见 TESTING.md。
