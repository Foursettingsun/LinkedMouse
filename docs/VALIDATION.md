# 0.1.7 输入助手、入屏响应与双向提示验证

日期：2026-10-28，单台 Windows 11 x64，实际 DPI 192（200%）。本页记录单机可复现检查；物理双机验收仍见 TESTING.md。

## 本版原因与实现

- 任务管理器可能以 High 完整性运行，普通输入进程为 Medium。新增通过 UAC 启动的独立输入助手，运行采集、注入与原生特效；蓝牙/TLS、剪贴板、文件和身份保持在原普通核心。只开放有帧长限制的本地输入管道，ACL 拒绝网络登录，双方核对 Windows 管道进程 ID 与父进程启动时间。
- 入屏旧位置修正与新鲜移动曾共用推进上限。现在保留边缘和首步限幅，之后新位移立即作用，旧误差单独收敛；倍率和 DPI 只按各自坐标语义转换。预热/普通模式使用同一阻力，支持 0；旧预热模式迁移为实际生效的 4。
- 冷启动资源创建可能耗掉闪光时间。现在预热只准备资源，闪光从首个可见帧重新计时；到达通知由已校验起点触发，发送端等待有效接管确认。1 秒拖尾仍从实际接管计时。
- 参照上游 HUD 加入英文提示与蓝粉样式。加载期间只保留最新事件，旧定时器不隐藏新提示，设备名按文字插入，窗口不激活且鼠标穿透。
- 本地启动器原先跟随尚未完成的源码版本目录，并隐藏启动 GUI；继承的 ELECTRON_RUN_AS_NODE 即使为空也可能令 Electron 进入 Node 模式。启动时改为验证完整构建、正常显示，并从子进程环境移除调试变量。窗口加载失败有可见提示，再次启动恢复最小化/托盘窗口。

## 0.1.6 历史：光标可见性验证

日期：2026-10-28，单台 Windows 11 x64，实际 DPI 192（200%）。

## 原因与修复

控制器原先在接收端返回时只清理输入注入，没有独立管理该屏幕的空闲光标，留下边缘残影。停放窗口也没有处理自己的 WM_SETCURSOR。实显检查另外复现：后台线程调用 SetCursor(NULL)，Windows 当前显示光标仍可能保持 CURSOR_SHOWING=1，窗口命中已是停放窗口，指针位置保持。

新实现处理停放窗口光标消息，选择透明光标后移除指针，并发送一次带既有 MARK 的零位移 MOVE 刷新系统光标归属；输入钩子和 Raw Input 已忽略该标记。不会引入坐标移动、鼠标按钮或按键。没有使用 AttachThreadInput、ShowCursor 计数循环或窗口激活。

离开接收屏幕后隐藏状态与本次可信控制会话绑定；预热不显示，真实到达或本机实体活动时恢复。连接与策略失效会释放状态，独立采集线程的存活计时也覆盖此状态。

## 已通过

- 51 组核心自检。新增 4 组覆盖原生窗口消息的箭头/手型/文本/尺寸光标、边缘命中、不激活、100 次重复隐藏/释放、停放窗口物理尺寸及销毁释放。
- 控制器回放覆盖 A 驱动 A→B→A、B 驱动 B→A→B、手动返回、预测返回、旧协议边缘返回、过期包隔离；预热及后台检查保持离开端隐藏，实际到达恢复。
- 本机物理输入回调恢复光标且不调用位置写入；断线、锁定、鼠标禁用、会话关闭、存活计时到期和退出清理隐藏状态。
- `--cursor-visibility-test` 的 21 个实际 Windows 场景，三个独立进程均通过。覆盖后台已有空光标状态、32/64/128 像素自定义光标、客户区与四侧非客户区的 WM_SETCURSOR、定期刷新、正常返回和旧消息。以 GetCursorInfo.flags 的 CURSOR_SHOWING 位验证完整隐藏；hCursor 可能保留历史句柄，不能单独用它判断。

接口依据：[SetCursor](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setcursor)、[WM_SETCURSOR](https://learn.microsoft.com/en-us/windows/win32/menurc/wm-setcursor)、[CURSORINFO](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-cursorinfo)。

| 实现 | 显示后该透明位置 | 结果 |

| 原项目 Flash.cs | `37,51,67` | 底色保持 |
| LinkedMouse 0.1.4 图层 | `255,255,255` | 复现白色矩形 |
| LinkedMouse 0.1.5 原生 Alpha 图层 | `37,51,67` | 底色保持 |

`crossings.firstDisplayedMoveMs` 表示首次过渡定位请求被接收器接受的本机时刻，**不证明显示器已经呈现**。`entryFrameMs` 是查询刷新率后选取的调度间隔；WinForms 定时器、系统负载、DWM 与无线传输可能延迟实际呈现，不能把模型中的 1–2 个间隔当作实测毫秒数。

实现参考：[Raw Input 的鼠标数据语义](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawmouse)、[GetMessageTime 的消息入队时间与回绕](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getmessagetime)、[GetDeviceCaps 的刷新率查询](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-getdevicecaps)。Raw Input 不采用 Windows 鼠标加速，远端倍率由“指针速度”调节。
