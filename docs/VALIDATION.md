## 白块复现与原项目对照

在同一个不抢焦点的受控窗口上，透明位置底色为 RGB `37,51,67`：

| 实现 | 显示后该透明位置 | 结果 |
| --- | --- | --- |
| 原项目 Flash.cs | `37,51,67` | 底色保持 |
| LinkedMouse 0.1.4 图层 | `255,255,255` | 复现白色矩形 |
| LinkedMouse 0.1.5 原生 Alpha 图层 | `37,51,67` | 底色保持 |

对照在 200% 缩放下进行；0.1.4 图层请求宽度 360/460/320 时均复现白底。原项目用法与旧适配的位图提交路径不同；新实现直接把预乘 BGRA 像素提交到原生分层窗口，避免背景颜色转换和 Form 显示流程。

- 自包含 Release 构建与 45 组原生自检通过；开发构建 0 错误、0 警告。
- 新增独立输入 STA 检查：真实主 STA 阻塞 380 ms 时，独立输入命令与心跳继续执行；测试不安装钩子、不注入桌面输入。
- 钩子替换故障注入：新配对完整成功前不卸载旧钩子；安装失败保留旧配对，系统复用句柄不会把新钩子误卸载。
- 保留 256 次速度/0–160 ms 接管延迟/四方向/混合 DPI 完整控制器回放；增加 .25/.5/1/2/3 倍率及 250 ms 晚到调度，首步距离保持有限，最终活动位移保留倍率。返回边界包不再补放到主机内部。
- 预热不显示特效，实际提交和预测返回分别成对触发离开/进入；重复旧轮次不重播。拖尾在接管后 1000 ms 到期，反向切换和取消隔离旧轨迹。
- 在真实但保持隐藏的透明分层窗口上校验像素提交、鼠标穿透/不激活标志与前台保持；阻塞绘制线程后排队的旧切换请求被作废；模拟绘制故障后，输入控制仍工作。视觉 PNG 由应用同一绘制器生成并检查，不是物理双机录像。
- 11 项 Node 检查通过：IPC、健康守护、宽限期/旧进程回复隔离、窗口生命周期、普通失焦不操作监听，以及旧核心版本检测。
- 8 个真实原生双进程回环场景通过，含配对、加密文件、拒收/重试、140 个中文文件、重连/忘记配对、诊断隐私；100 次后台健康请求期间原 PID/TLS 连接保持，健康钩子替换次数不增加，实际 Raw Input 注册有效。
- 真实 Electron 5 页、进度/重试/文字转义、预热和视觉设置、FileList 桥接通过；与另一原生进程配对后，一次最小化和 20 次关闭到托盘，原 PID/TLS 链路、输入心跳、钩子和 Raw Input 注册保持有效，全程没有点击桌面恢复。
- 最终便携 ZIP 的 CRC、包内原生核心与自检构建、安装包嵌入 ZIP 的逐字节 SHA-256 均核对一致；本地常用直接运行目录已同步到 0.1.4。
- 测试使用独立配置，GUI/回环禁用蓝牙和共享输入/剪贴板；所有移动回放使用隔离接收器，未向用户桌面注入测试鼠标。

诊断 `input.runtime` 提供输入线程/心跳，`input.background` 区分健康检查与真实钩子重建，`input.effects` 提供独立绘制线程/失败状态。`firstDisplayedMoveMs` 仍表示定位注入被接受的本机时间，不能证明显示器已呈现，也不能跨机器时钟相减作为显示延迟。

健康检查参考：[GetRegisteredRawInputDevices](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getregisteredrawinputdevices)。无输入的静止状态不被当作鼠标故障；正常窗口状态变化不主动重建连接。

## 0.1.3 历史验证

日期：2026-10-28。环境：单台 Windows 11 x64；本页区分代码/进程检查与物理双机验收。

- 原生自包含 Release 构建通过，39 组原生自检通过；开发构建 0 错误、0 警告。
- 新增 256 次完整控制器回放：速度 100/1500/4000/10000 逻辑单位每秒，接管延迟 0/16/80/160 ms，四方向、正反缩放组合、负坐标。接管时传入 50000 残余量并累计等待期运动，仍先在固定边缘定位；确认后的 30 单位移动保持目标 DPI 距离，返回预测一致，无旧过渡回放。
- 生产 InputOutbox 参与新回放；不可合并起点与普通位置分开，确认前位置拒绝，重复起点/提交/回执不重置，旧序号/旧轮次不能重新激活。点击、滚轮和拖拽按精确目标执行。
- 以假时钟和隔离接收器检查 30/60/144/240 Hz 的边缘保留、过渡中间采样和截止时间；更新目标不延长起步过渡，结束后活动移动直接定位。这是调度模型检查，不是实际显示器首帧测量。
- 直接调用生产 Capture 回调验证：钩子旧屏幕坐标不生成移动，Raw Input 的移动/按钮只转发一次且按序，校准排除旧位移但保留按钮释放；覆盖来源缩放与消息时钟回绕。
- 真实双向 TLS 的 19/31 字节碎片流上分别验证 v3 兼容流程与 v4 起点校准、确认前位移消耗、活动位置和预测返回；此项未经过物理蓝牙无线链路。
- 校准超时、错误连接、取消、锁定与过渡定位失败恢复输入，释放修饰键并停止旧过渡。
- 6 项 Node 测试、JavaScript/资源检查通过；8 个真实原生双进程回环场景通过，包含文件与后台重挂，核对钩子和 Raw Input 注册有效。
- 真实 Electron 五页、传输进度/重试/文字转义、预热设置和 FileList 桥接通过；最小化、关闭到托盘后原生通信和后台注册仍有效，全程未点击桌面。
- 便携 ZIP 的 CRC 检查通过；包内程序、界面归档和原生核心与本次构建一致。安装包嵌入的 ZIP 载荷与便携版逐字节 SHA-256 一致；本地常用直接运行目录已同步到 0.1.3。
- 测试采用独立配置与隔离鼠标接收器；真实 GUI 测试禁用共享输入/剪贴板和蓝牙，不向用户桌面注入测试鼠标。

`crossings.firstDisplayedMoveMs` 表示首次过渡定位请求被接收器接受的本机时刻，**不证明显示器已经呈现**。`entryFrameMs` 是查询刷新率后选取的调度间隔；WinForms 定时器、系统负载、DWM 与无线传输可能延迟实际呈现，不能把模型中的 1–2 个间隔当作实测毫秒数。

实现参考：[Raw Input 的鼠标数据语义](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawmouse)、[GetMessageTime 的消息入队时间与回绕](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getmessagetime)、[GetDeviceCaps 的刷新率查询](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-getdevicecaps)。Raw Input 不采用 Windows 鼠标加速，远端倍率由“指针速度”调节。
