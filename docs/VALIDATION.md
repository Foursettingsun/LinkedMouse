# 0.1.15：跨屏点击与后台恢复授权

日期：2026-10-31。Windows x64 本机，真实双进程回环；未执行双机 BLE 或整机睡眠。

## 现场依据与修复

- 界面保持后台运行时，普通核心仍可能因健康判断或真实故障自动重启；新的管理员助手进程会重新请求授权。下载/构建新版不会替换内存中的旧界面和其自带核心，需要退出旧版使修复生效。没有旧核心退出原因日志时，不能把一次重启直接断言为休眠误判。
- 生产 `Capture.MouseHook` 在原始位移捕获模式直接吞掉按钮消息，只依赖 `OnRawMouse` 的按钮标志转发。钩子有点击、原始按钮包缺失时会丢掉所有按下/松开，而原始位移/滚轮继续工作。新增生产回调回归在旧实现上以退出码 1 复现，失败为 `hook-only press/release was lost while raw motion capture was active`。这证明存在匹配症状的代码缺口；尚未记录用户实机驱动的原始事件流。
- 五个按钮统一由钩子转发，原始按键标志只更新物理拖拽状态。原始位移与滚轮、8ms 批次、二进制编码、动作前位置刷新和 BLE/TLS 参数保留；没有用于等待原始按钮包的定时器或重传。
- 新按下清除旧捕获遗留的松键抑制，避免安全桌面/睡眠中错过旧松键后吞掉新点击的释放。自身 MARK 输入依旧跳过，原始包迟到不会重新发送点击。
- 鼠标按钮注入检查 SendInput 的成功数量；失败不再计入成功接收，并返回本机、告知来源。清理中的某个松键失败不会阻断其余按钮。诊断新增按钮来源/捕获数及注入尝试、失败和持有数。
- 自动核心重启传入后台恢复标记：启动普通输入并保留管理员偏好，状态为 `needsConsent`；不自动启动提权助手。现有“启动输入助手”按钮提供明确的用户恢复操作。普通初次启动策略与真实故障检测保留；休眠正常恢复仍复用已有进程。
- 管理员助手正在启动时禁用重复请求；启动结束后开关重新可用，已活动的助手不能重复启动。

## 已验证范围

- 95 组原生通过。新增 6 组覆盖五按钮/双击的钩子独立输入、驱动注入标志、原始重复包/标记回环、遗留松键、生产采集→编码→合并队列→校准接收端的拖拽落点、拒绝注入与全部按钮清理；新增 1 组覆盖保留偏好、普通输入继续运行及主动重启真实测试助手。
- 26 项 Node 通过。新增 2 项用完整子进程事件流程检查普通启动无后台标记、故障重启携带标记、睡眠中退出后恢复时也携带标记。既有休眠超时、遗漏电源事件与宽限到期回归保留。
- 真实双原生进程回环 11 个场景通过，包括管理员偏好为真时的后台启动不产生助手、实际终止隔离核心后的自动重启、身份/偏好保留与可信重连；原有加密文件传输、内容校验与 100 次后台健康请求继续通过。
- 真实 Electron 五页和管理员助手的 4 种状态检查通过，确认授权期间禁用重复请求、结束后开关重新可用；既有模拟电源恢复、文件页重复按钮、磁盘拖入/内容校验与托盘后台生命周期回归继续通过。
- 本地记录为 `artifacts/click-0.1.15-*`。硬件鼠标、物理双机 BLE 延迟和整机睡眠没有实测，不把模拟回调/单机回环宣称为端到端硬件测量。

接口依据：[鼠标钩子事件](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc)、[钩子按钮/注入标志](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-msllhookstruct)、[SendInput 返回值与完整性级别限制](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)。具体缺口来自本地代码和回归，未把这些接口文档当成用户驱动丢包的证据。

# 0.1.14：休眠恢复避免无故重新提权

日期：2026-10-30。Windows x64 单机；未让整台机器进入睡眠/休眠。

## 原因与实现

- 界面健康检查未处理电源事件，休眠前未完成的请求或唤醒时的过期快照可能触发杀死核心；核心重新启动时重新启动管理员助手，造成新的 UAC。新增 Node 回归在旧版上失败。
- Electron 现绑定 suspend/resume：睡眠前请求安全返回本机，暂停健康轮询；唤醒后使旧探测失效并刷新原后端，复用已有核心。恢复后的 15 秒内不以暂时未响应杀死核心。额外处理大于 8 秒的轮询间隔和遗漏 resume 的有界恢复，避免旧计时回调抢先运行或健康判断永久暂停。
- 原生健康计时改用 `QueryUnbiasedInterruptTime`，不计睡眠/休眠；结合显式 `GetTickCount64` 的系统睡眠偏移，在电源事件回调之前识别唤醒，给予 5 秒运行时间宽限。用于运行态心跳、父进程心跳和恢复观察；实际位移/输入批次、绘制及蓝牙计时保持原有逻辑。
- RPC 仅在确认唤醒后的超时路径，继续等待同一个请求一次，不重新发送。管道真断开、父进程退出及普通运行中的卡死保持原有处理；恢复宽限到期后超时重新生效。
- `input.runtime` 增加 `heartbeatClock:awake` 和 `resumeGrace` 诊断。没有关闭 UAC、安装服务/计划任务或保存管理员凭据；启动新进程时的正常授权保持。

## 验证结果

- Node 24 项通过，新增 4 项覆盖跨休眠的待决健康请求、缺失通知、暂停轮询和遗漏 resume 后恢复真实故障检测。
- 原生 88 组通过，新增睡眠/休眠时间跳变、5 秒宽限到期、Windows API 可用性及真实助手三轮模拟恢复后 PID 不变检查。原有卡死助手退出和本机输入回退检查继续通过。
- 真实 Electron 五页通过，向当前 Electron 进程发送 3 轮模拟 suspend/resume，核心 PID、输入健康和已配对的回环连接保持。原文件页 100 次刷新/14 种组合及实际文件操作继续通过。
- 真实双原生进程回环 9 个场景通过，包含可信重连、文件逐字节校验和 100 次后台健康请求。
- 最终记录位于本地 `artifacts/power-0.1.14-*`；早期计时 API 导出兼容性候选未采用。自动结果不代表已完成物理睡眠/休眠、不同电源模式或双机 BLE 唤醒后的 UAC/延迟实测。

接口依据：[不含睡眠时间的 Windows 计时](https://learn.microsoft.com/en-us/windows/win32/api/realtimeapiset/nf-realtimeapiset-queryunbiasedinterrupttime)、[Windows 启动时间](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-gettickcount64)。

# 0.1.13：传输任务的操作按钮重复

日期：2026-10-29。Windows x64 本机真实 Electron 界面验证。

## 原因和修复

- 任务列表通过 HTML 缓存避免重复重建，但已完成任务的操作按钮由另一个循环在缓存判断之后直接追加。当任务内容不变、其他后台状态更新时，列表保持原节点而操作区不断增长。新增回归在旧实现上复现：100 次更新后，同一接收完成任务存在 101 组操作。
- 接收/取消、失败重试、完成后定位/删除以及移除记录，现全部由 `transferActionsTemplate` 随任务模板统一生成。移除后置 DOM 追加；缓存内容包含完整操作区，重复状态不会额外创建节点，状态变化会替换相应按钮。
- 新增真实渲染器回归：14 种方向/状态组合、100 次连续更新、原 DOM 保留、任务重排、5 次页面往返、同一任务切换不同状态及清空列表。检查每条任务操作区数量、按钮种类与任务 ID。
- 同时修正界面检查程序退出行为：捕获失败后明确停止隔离核心并返回非零状态，避免 Electron 正常退出掩盖失败。旧实现的上述回归已确认返回退出码 1。

## 结果

- Node 20 项、JavaScript 检查和原生 85 组自检通过。
- 真实 Electron 五页及新传输操作区回归通过；接收完成后每种操作按钮恰好一个，实际文件定位、回收站删除、移除记录与发送端保护通过。
- 真实磁盘 FileList 经沙箱桥和两端原生核心完成多文件/目录传输，逐字节内容校验通过；最小化、20 次关闭到托盘和连接健康检查通过。
- 基线失败记录：本地 `artifacts/file-actions-0.1.13-baseline.*.log`；修复后的界面和检查记录：`artifacts/file-actions-0.1.13-*`。本次生产逻辑改动位于界面渲染，核心仅更新应用版本，未调整文件传输协议或输入参数。

# 0.1.12：拖尾视觉微抖过滤

日期：2026-10-29。Windows x64 单机；真实透明图层检查为 200% DPI。

## 实现和边界

- 新增的静止/停止噪声检查在旧版上失败：微小鼠标报告会形成碎线，并不断刷新尾部。现在相对最后有效视觉坐标使用 1.5 逻辑像素空间范围，按 DPI 缩放；被忽略的噪声不刷新有效移动时刻，也不使历史缓存失效。
- 连续小步相对最后有效位置累计，避免逐个丢掉单像素慢移。超过范围的输入立即接受，没有时间窗口、重传或等待。仅拖尾视觉末端允许在该小范围内保持稳定；真实坐标、鼠标操作与发送路径不变。
- 最新临时曲线点在检测到小幅交替转向/坐标反复时，才向相邻点连线投影，偏离不超过微抖范围。连续同向弧线保留；已完成历史不回写。移除细小报告后，明确的直角/反向保留转折，避免凭空产生过冲。
- 忽略的微抖仍推进已观察时间，防止更旧的大位移绕过排序；新接管重新初始化状态。原 140ms 尾部、1 秒效果、容量/弧长上限及绘制线程隔离保持。

# 0.1.11：稀疏快移的连续曲线与绘制开销

日期：2026-10-29。Windows x64 单机；真实透明图层检查为 200% DPI。

## 原因与实现

- 0.1.10 的路径仍在相邻采样间画长直线：小于约 11.5° 的转角直接跳过圆滑，其他转角仅处理 3 个逻辑像素。新增大弧线像素检查在旧实现上失败，证明稀疏快速轨迹仍是多边形；旧版通过的无断点/无过冲检查未覆盖这一现象。
- 新 `TrailCurve` 使用向心 Catmull–Rom 导数生成三次曲线；按节点共享切线，并限制控制柄长度与侧向偏离，单独处理重复点、同刻样本和反向。自适应细分以 0.5 物理像素为目标，最多 10 级。最新一段立即使用单边端点切线绘制，收到下一点后仅最终确定这一段；已完成历史段固定。
- 每个曲线段的细分结果独立缓存；按 140ms 与弧长上限裁切同一条曲线。包围框和画笔共用帧缓存，不再重复拟合/展开路径。头部使用最新已收位置，无预测或输入等待；接管后 1 秒效果保持。
- 首版曲线候选的稀疏绘制耗时高于旧版，因此继续改为扫描每行与线段覆盖胶囊的交集。保留弧长着色、最大覆盖 Alpha 和预乘格式；独立逐像素距离参考验证水平、垂直、对角、近轴、裁切和交叉路径，Alpha 误差不超过 1。
- 此次没有修改实际输入采集、8ms 默认批次、控制权状态机、跨屏阻力同步和蓝牙传输参数。

## 0.1.6 历史：光标可见性验证

日期：2026-10-28，单台 Windows 11 x64，实际 DPI 192（200%）。

## 原因与修复

控制器原先在接收端返回时只清理输入注入，没有独立管理该屏幕的空闲光标，留下边缘残影。停放窗口也没有处理自己的 WM_SETCURSOR。实显检查另外复现：后台线程调用 SetCursor(NULL)，Windows 当前显示光标仍可能保持 CURSOR_SHOWING=1，窗口命中已是停放窗口，指针位置保持。

新实现处理停放窗口光标消息，选择透明光标后移除指针，并发送一次带既有 MARK 的零位移 MOVE 刷新系统光标归属；输入钩子和 Raw Input 已忽略该标记。不会引入坐标移动、鼠标按钮或按键。没有使用 AttachThreadInput、ShowCursor 计数循环或窗口激活。

离开接收屏幕后隐藏状态与本次可信控制会话绑定；预热不显示，真实到达或本机实体活动时恢复。连接与策略失效会释放状态，独立采集线程的存活计时也覆盖此状态。
