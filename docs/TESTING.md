# 两台电脑的验收记录

本文件是物理设备联调清单，不代表已经通过。

## 基本环境

- A/B 的 Windows 版本、蓝牙适配器型号与驱动版本。
- 确认 A/B 都支持 BLE，至少一台支持广播。
- 两机使用不同网络，保持原有上网连接。
- 记录两端 VPN/代理名称、系统代理或 TUN 模式。

## 连接

1. 默认关闭 Wi-Fi 加速，发现并配对；两个配对码一致。
2. 只在一端确认不能启用共享；拒绝和超时可以正常结束。
3. 退出重开后可信设备自动重连；主动断开后不会马上抢回连接。
4. 在 A 开 VPN、B 开 VPN、两端都开 VPN 的情况下分别验证蓝牙。
5. VPN 开关变化、Wi-Fi 上网变化时，蓝牙路径保持可用。
6. 开启 Wi-Fi 加速，验证 Direct 通道和原有上网/VPN 并存；失败时继续蓝牙。

## 四项功能

- 上下左右方向跨屏、不同分辨率和缩放、单显示器与多显示器外边缘。
- 左右键、中键、前进后退键、纵横滚轮、按住按钮拖动。
- 中英文、Shift/Ctrl/Alt/Win、复制粘贴和输入法切换。
- 双击返回快捷键、托盘返回、本机锁定、断网释放按键。
- A/B 双向中文多行文字、截图、透明 PNG；密集连续复制保持最终内容一致。
- 文件、文件夹、空文件、中文文件名、同名接收、拒绝、取消、重新发送。
- 大文件传输期间操作键鼠，记录响应和排队情况。
- 睡眠唤醒、蓝牙关闭重开、辅助进程异常退出后的恢复。

## 性能对照

### 0.1.3 边缘起步与快移验收

1. 两端从托盘选择“退出”后运行 0.1.3；核对偏好设置中的版本，开启双向预热、关闭 Wi-Fi 加速，先单独验证蓝牙。
2. 主机在右、副机在左，分别慢速、正常速度和快速横移，每种至少 25 次，再交换输入源并测试四方向、不同分辨率及 100/125/150/200% 缩放。
3. 用屏幕录像或高速摄像检查：副机先从相邻边出现，再接上当前移动；确认等待期的历史位移不应集中补放。记录第一次可见光标的位置和下一帧轨迹，不能只核对最终坐标。
4. 分别在空闲、传大文件、同步截图时重复快移；记录校准确认时间。确认前的普通移动本版会消耗；确认后移动距离与速度不应被截断。返回预测与副机目标应一致。
5. 跨屏后马上点击、滚轮、按住拖动、Ctrl/Shift 组合输入，再快速返回；点击与释放应落在各自目标，不能落到过渡的中间位置。
6. 两端分别最小化或点关闭隐藏到托盘，不点击桌面，重复跨屏与返回；检查原后台修复仍有效。
7. 正在接管或过渡时断开、锁定、改布局，检查恢复输入、释放按键、无迟到旧位置回跳。再与 0.1.2 在相同设备/场景对照。
8. 导出两端诊断：记录 crossings.calibrated、consumedBeforeOrigin、entryFrameMs、firstDisplayedMoveMs，以及 background.rawAccepted/rawDiscarded。firstDisplayedMoveMs 是首次过渡定位注入时间，不代表 DWM/显示器已经呈现；不能跨机器时钟相减当作显示延迟。

Raw Input 不采用 Windows 鼠标加速曲线，远端手感可用“指针速度”调整；记录两端缩放、鼠标 DPI 和倍率以便复现。

### 0.1.2 历史双向预热与后台验收

1. 两端退出旧版并运行 0.1.2，在“鼠标与键盘”开启“双向预热”，宽度先选自动。原有配对可保留。
2. 主机在右、副机在左时，主机靠近左侧区域：主机继续处理鼠标、键盘和点击，副机无光标跳动、无输入；移开区域应取消预热。上下、左右方向分别检查。
3. 真正向外越界后，检查光标从副机正确边缘接管；快速移动的真实越界距离允许进入屏幕内部，预热阶段的历史移动不得整包重放。
4. 在副机上移动同一个物理鼠标返回主机，连续快速往返至少 100 次，检查无固定冷却停顿、无旧序号回跳、无卡键。
5. 按住 Ctrl/Shift 跨屏后组合输入并返回；拖动窗口/选中文字时保持当前电脑，释放按钮后再跨屏。
6. 分别将两端窗口最小化、点关闭隐藏到托盘，不点击桌面，直接跨屏；比较诊断 `input.background` 的钩子和 Raw Input 注册、重挂次数。
7. 预热时撤回、锁定、关闭蓝牙、锁屏/解锁、更改显示器布局；检查接管取消、恢复后可再次准备，旧预热包不激活输入。
8. 传文件和同步截图时重复以上操作，记录预热命中率、位置合并、预测返回和 RTT。关闭预热与 0.1.1 做同设备对照，单独记录窗口后台场景。

### 0.1.1 历史验收

先验证 0.1.1 修复，再与其他软件比较：

1. 两端退出旧版，安装或解压 0.1.1，关闭 Wi-Fi 加速，保留原配对身份。不要同时运行两个版本。
2. 分别设置左、右、上、下位置；每个方向慢速跨屏 10 次、快速跨屏 25 次。检查首次定位来自对应边缘，连续移动没有等待确认后的历史位移突发。
3. 检查 100/125/150/200% 缩放、不同分辨率、负坐标显示器。快速运动本身可以进入屏幕内部，不应把正常移动距离误认为错误落点。
4. 复制大截图或发送文件时重复切换，再验证拖动窗口、选中文字、按住按钮移动、Ctrl/Shift 组合键；按钮释放位置和距离保持正常。
5. 双击右 Ctrl 返回；切换期间拒绝接管、关闭蓝牙、休眠/唤醒，检查恢复本机且没有卡键。
6. A/B 同时导出诊断，比较 `input.crossings` 的方向、落点、`landingObserved`、`firstMoveMs`、`acceptMs`、`endReason`，以及 `inputQueues.metrics` 的合并/过期计数和最大排队时间。`landing-unconfirmed`/`landing-failed` 需要单独排查权限、输入桌面及驱动。
7. 用同一组设备记录 0.1.0 和 0.1.1 的切换响应及 RTT 分位数。屏幕录像/高速摄像可用于显示时序；本机时钟与网络 RTT 不等于完整显示延迟。

在相同两台电脑、距离、无线环境、VPN 模式和工作负载下，对照 TwinDesk 2.3.0。
记录中位数/P95 往返延迟、跨屏操作响应、图片/文件吞吐、重连耗时和托盘内存。
“P95 往返延迟”是应用消息 RTT，不等于完整的鼠标运动到屏幕显示延迟。
原版不支持蓝牙图片剪贴板时，应记录为能力差异，不能虚构吞吐对照。

只有真实记录支持的项目才填写“优于原版”；目前不预填提升百分比。
